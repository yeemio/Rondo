## 1. 产品目标与完成条件

Rondo 面向中国孩子提供数学、逻辑推理、计算思维与 AI 启蒙学习。本次 MVP 面向小学六年级初学者及监护人：数学以实际苏教六上教材为入口，编程以 GESP C++ 二级真题与解析为入口，AI 以历史、机制和使用判断递进组织。内部复用先修关系，不用考级等级替代数学路径；更广年龄适用性仍待验证。

孩子应能从一个清楚的问题出发，预测、操作对象或步骤、核对结果、解释理由，并在不同情境中再用一次；监护人能区分独立完成、受帮助完成、过程完成及尚未掌握。观看动画、点完流程、一次答对和程序样例通过，都不能自动升级为掌握。

当前 MVP 的完成条件是：[已定三线范围](planning/RONDO-MVP-SCOPE-20261028.md#6-可观察的-mvp-完成条件)接入同一浏览器产品，数学教学位置、真题作答与解析、AI 活动完整可用；题目、领域状态、判分、提示与回看一致，学习事实可保存和恢复。代表活动通过不替代全部范围完成。真实家庭使用和学习效果仍需单独证据，当前范围确认不签署这些结论。

## 4. 学习、内容和产品生命周期

学习旅程：先修诊断 → 选择适合的任务 → 首次预测 → 操作确认 → 服务端核对 → 修正与解释 → 回看 → 陌生任务 → 实际到期的延迟迁移 → 监护观察与下一步安排。断线、暂停、失败和结果未知保留原身份及证据，不能补造成成功。

内容生命周期：教学目标与先修 → 题目/场景/私有真值 → 内容核对 → 独立候选 → 产品接线 → 适用技术验证 → 教学与交互验收 → 正式可用 → 反馈修订 → 退役或撤回。它与运行时 DRAFT/REVIEWED/AVAILABLE 等状态关联，但 PM 文档不能直接改变发布状态。

项目生命周期从需求与架构延伸到内容、开发、整合、体验、家庭试用、交付、运营、改版和退役；各阶段的当前事实与进入条件统一见[生命周期地图](RONDO_PRODUCT_LIFECYCLE_MAP.md)。

## 6. PM 如何持续管理

1. 新范围、稳定交付、审查终裁、运行读回、Owner 体验结论、家庭观察或责任变化出现时，只读取相关差集，更新对应阶段和目标。
2. 每次状态变化绑定对象/版本或候选、证据、责任人、结果范围和下一动作；缺失的字段如实记未提供，不用 ACK、任务数量或文档日期推断完成。
3. 有效旧证据在原候选与覆盖下复用。新内容变更只补受影响验证；PM 不重审整包、不巡检移动候选、不例行全仓扫描。
4. 冲突先比较身份、范围与后续明确替代关系。当前状态只保留一个；旧失败和已撤回 ACCEPT 作为历史保留。把日志末尾附一段新结论却保留正文旧“当前状态”，不算同步完成。
5. 技术审查、课程语义、实际交互和学习效果分开接受。即使测试通过，Owner 否定体验时也必须保留相应待验/返工状态；反之，视觉待验不自动撤回已证功能修复。
6. 架构师只裁定会改变目标、接口保证、范围或责任的真实分歧。常规可逆实现由当前具名实施者连续推进，不逐课等待 PM 批准。

更新由已到达的新证据或 Owner 请求触发。2026-10-27 曾建立每小时一次的有界交付跟进；2026-10-28 Owner 明确取消，应用内 `rondo` 已暂停，未经新的明确要求不恢复。本次同入口验收改绑新版 MVP 范围，见[目标表第 5 节](status/RONDO-PRODUCT-TRACKER.md#5-本次同入口验收与跟进)；旧 L1–L4 里程碑保留为历史，不成为新 MVP 的强制前置。跨聊天或对外发送仍须明确通信授权与可用通道。
